# Upload request logs to a bucket

Request logs live only on the instance's disk, so they are lost when an ephemeral instance is replaced. The new `observability.logs.request-log-bucket` setting (legacy key `request-log-bucket`) takes a `gocloud.dev` bucket URL. The `gcsblob`, `s3blob`, and `fileblob` drivers are linked in, and credentials come from each provider's standard environment. Logs are still written locally first. A background uploader then copies each completed request or error log to the bucket under its file name and deletes the local copy. The uploader runs when a log completes, again every minute to retry failed uploads, and once more when the server stops, until the shutdown context ends. An empty value keeps today's local-only behavior. A hot reload that changes the URL aborts the old uploader without draining it, and the new uploader picks up the files left behind.

So that a finished-looking file never holds partial content, both the non-streaming and streaming write paths now assemble the log in a `request-log-*.tmp` file. They reserve the unique `.log` name only at the end and then rename the temp file over it. An empty `.log` is therefore a reservation that has not been filled yet, and the uploader skips it. When the server starts, before it serves any requests, it deletes orphaned artifacts from requests that were still being logged when the last process stopped: `request-log-parts-*` directories, `request-body-*`, `response-body-*`, and `request-log-*` `.tmp` files, and empty reserved `.log` files. The uploader's first pass then uploads and deletes any completed logs that a previous instance stopped before uploading. This cleanup runs even without a bucket. It assumes that no other running process shares the logs directory.

Only names produced by the request logger qualify for upload, so `main.log` and its rotations stay local. Uploaded logs are no longer available through the management log endpoints, and `error-logs-max-files` only limits the error logs that are still waiting locally. This deliberate fork addition under [ADR-0003](0003-minimize-fork-divergence.md) stays within `internal/logging`, with small hooks in server construction, reload, and stop. Adding the dependency also raised several shared modules, including `fsnotify`, `golang.org/x/*`, and `google.golang.org/protobuf`, to the minimum versions that `gocloud.dev` requires.
